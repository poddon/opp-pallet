# Тестирование ОПП

Приложение запускает два портала и хранит задания, прохождения и ответы в PostgreSQL.

| Портал | Адрес на сервере | Доступ по умолчанию |
| --- | --- | --- |
| Студент | http://localhost:8004 | По локальной сети. Для подключения используйте IP компьютера с запущенным EXE |
| Администратор | http://localhost:8005 | С компьютера, на котором запущен EXE |

## Запуск в Windows

Скачайте [OPP-test.exe](https://github.com/poddon/opp-pallet/releases/download/site-latest/OPP-test.exe). Подготовьте существующую базу PostgreSQL и текст согласия на обработку персональных данных в UTF-8, который используется в вашей организации. Роль PostgreSQL должна иметь права на создание таблиц в своей схеме и изменение существующих таблиц приложения.

В PowerShell, в папке с EXE:

```powershell
$env:OPP_ADMIN_PASSWORD = 'Замените_на_отдельный_пароль'
$env:PGPASSWORD = 'Пароль_роли_PostgreSQL'
.\OPP-test.exe start --ip localhost --port 5432 --name opp_tests --user postgres --consent-file .\consent.txt
```

`--port` задаёт порт PostgreSQL. Порталы всегда запускаются на 8004 и 8005. `--name` задаёт имя базы. Если `--user` и `PGUSER` пропущены, имя роли совпадает с именем базы. Пароль PostgreSQL также можно передать через `--password`, администраторский через `--admin-password`, путь к согласию через `OPP_CONSENT_FILE`. Параметр `--sslmode` задаёт TLS подключения к PostgreSQL.

Пример вызова с внешними параметрами:

```powershell
& 'C:\Users\Aang\Desktop\scripts\OPP-test.exe' start --ip localhost --port 5432 --name maxbot --password 'пароль_PostgreSQL' --consent-file .\consent.txt
```

Для входа на портал студента с телефона откройте `http://IP-КОМПЬЮТЕРА:8004` в той же сети. Разрешите входящие подключения к TCP 8004 в профиле закрытой сети Windows. Для отдельного администраторского компьютера можно задать интерфейс через `--admin-bind` и предоставить доступ к порту 8005 через доверенную сеть или HTTPS-прокси.

## Проведение тестирования

1. Войдите в админский портал с отдельным паролем. Существующие группы импортируются из таблицы результатов. Новые добавляются в разделе «Открыть тест».
2. Выберите группу, тематический тест и время доступа. По умолчанию доступ открыт на 30 минут. В разделе «Активные тесты» его можно закрыть раньше для выбранной группы.
3. Студент выбирает свою группу, подтверждает согласие и начинает тест. На вопрос отводится до 55 секунд в пределах общего срока доступа. Прогресс и ответы фиксируются по мере прохождения. При закрытии теста уже сохранённые ответы доступны в результатах.
4. В «Результатах» можно сочетать фильтры по ФИО, группе, тесту, статусу и датам, открыть ответы или скачать отфильтрованную таблицу Excel. Для архивных результатов доступны данные, которые уже были сохранены в PostgreSQL.

## Очистка мониторинга

Сначала посмотрите количество устаревших записей старого мониторинга. Критерий — старше 24 часов без привязки к новым назначениям.

```powershell
.\OPP-test.exe cleanup --ip localhost --port 5432 --name opp_tests --user postgres
.\OPP-test.exe cleanup --ip localhost --port 5432 --name opp_tests --user postgres --apply
```

Первая команда выполняет только подсчёт. Вторая удаляет найденные записи из `quiz_live`. Обе используют заданный пароль PostgreSQL. Завершённые тесты, ответы и архивные результаты сохраняются.

## Сборка

```powershell
cd desktop
go test ./...
go build -trimpath -o OPP-test.exe .
```

GitHub Actions тестирует сервер с PostgreSQL и собирает EXE для Windows x64. После успешной сборки из `main` файл публикуется в релизе `site-latest`.
