# Тестирование ОПП

`OPP-test.exe` запускает два отдельных портала и хранит задания, прохождения и ответы в PostgreSQL (Supabase не используется).

| Портал | Адрес на сервере | Доступ по умолчанию |
| --- | --- | --- |
| Студент | http://localhost:8004 | По локальной сети. Для подключения используйте IP компьютера с запущенным EXE |
| Администратор | http://localhost:8005 | С компьютера, на котором запущен EXE |

Порталы разделены: у студента нет доступа к API администратора, а вход в админку выполняется только по паролю, без имени пользователя.

## Запуск в Windows

Скачайте [OPP-test.exe](https://github.com/poddon/opp-pallet/releases/download/site-latest/OPP-test.exe). Подготовьте существующую базу PostgreSQL. При запуске приложение подключается к ней и само создаёт недостающие таблицы (`quiz_*`). Роль PostgreSQL должна иметь права на создание таблиц в своей схеме и изменение существующих таблиц приложения.

Запуск с внешними параметрами (подставьте свои значения):

```powershell
.\OPP-test.exe start --ip localhost --port 5432 --name ИМЯ_БАЗЫ --password ПАРОЛЬ_POSTGRESQL
```

| Параметр | Назначение | По умолчанию |
| --- | --- | --- |
| `--ip` | адрес PostgreSQL | `localhost` |
| `--port` | порт PostgreSQL | `5432` |
| `--name` | имя существующей базы | `opp` |
| `--user` | роль PostgreSQL | совпадает с `--name` (или `PGUSER`) |
| `--password` | пароль PostgreSQL | `PGPASSWORD` |
| `--admin-password` | отдельный пароль админки, от 12 символов | `OPP_ADMIN_PASSWORD`, иначе пароль PostgreSQL |
| `--consent-file` | файл с текстом согласия на обработку ПД | `OPP_CONSENT_FILE` |
| `--sslmode` | TLS подключения к PostgreSQL | `disable` |
| `--student-bind`, `--admin-bind` | интерфейсы порталов | `0.0.0.0` и `127.0.0.1` |

Порталы всегда запускаются на портах 8004 (студент) и 8005 (администратор). Если отдельный пароль админки не задан, вход в портал администратора выполняется по паролю PostgreSQL — об этом сообщается в окне при запуске.

При двойном щелчке по EXE без параметров откроется пошаговая настройка подключения. Если рядом есть старый `pg-config.json`, его значения предлагаются автоматически. При ошибке подключения в окне будет показана причина.

Для входа на портал студента с телефона откройте `http://IP-КОМПЬЮТЕРА:8004` в той же сети. Разрешите входящие подключения к TCP 8004 в профиле закрытой сети Windows.

## Проведение тестирования

1. Войдите в админский портал. В разделе «Открыть тест» сохраните утверждённый текст согласия на обработку персональных данных (или передайте файл через `--consent-file`; текст из админки имеет приоритет). Без согласия студент не сможет начать тест, а принятая им версия текста сохраняется вместе с попыткой.
2. Выберите направление из списка (1C, Электромонтаж, БПЛА, ЗРА, WEB, ЧПУ, ПромБез) и отметьте номер группы (26-1, 26-2) или впишите другой номер вручную, например 26-8. Группа получает название как в ведомости — `1C-26-8`, `Электромонтаж-26-2`. Нажмите «Добавить в список» и повторите для других направлений. Всем выбранным группам назначается общий тест из 50 вопросов по всем модулям. По умолчанию доступ открыт на 30 минут.
3. В разделе «Активные тесты» видны все открытые тесты, время открытия, время автоматического закрытия и остаток. Кнопка «Закрыть тест» закрывает тест раньше только для выбранной группы. По истечении срока тест закрывается автоматически, незавершённые попытки получают статус «Тест закрыт», уже данные ответы сохраняются.
4. Студент выбирает свою группу, подтверждает согласие и начинает тест. На вопрос отводится до 55 секунд в пределах срока доступа. Уход со страницы засчитывается как списывание: появляется экран «СПИСАНО» с сиреной, результат — 0%.
5. В «Результатах» фильтры сочетаются: ФИО, статус, период и группы. В фильтре групп каждое направление раскрывается по номерам групп, можно отметить отдельные номера или всё направление. Кнопка «Ответы» показывает ответы, разбитые по модулям, со счётом по каждому модулю и отметкой «Правильно», «Неправильно» или «Без ответа».
6. «Скачать Excel» выгружает файл с теми же фильтрами. Лист «Результаты» — общий процент и число правильных, неправильных и пропущенных ответов по каждому модулю. Лист «Ответы по модулям» — каждый ответ студента с модулем, вопросом, выбранным и правильным вариантом и итогом.

7. «Сформировать ведомость» выгружает смежную ведомость по итоговому тестированию в формате утверждённого бланка: отдельный лист на каждую группу с её названием (`1C-26-8`, `Электромонтаж-26-2`), дата тестирования, № группы, тема, студенты по алфавиту с % освоения и графой для подписи, доля сдавших на 70% и более (формулой) и строки для подписей руководителя проекта и старшего преподавателя. Учитываются выбранные группы, статус и период; если студент проходил тест несколько раз, берётся последний результат, списывание — 0%.

## Очистка базы

```powershell
.\OPP-test.exe cleanup --ip localhost --port 5432 --name ИМЯ_БАЗЫ --password ПАРОЛЬ_POSTGRESQL
.\OPP-test.exe cleanup --ip localhost --port 5432 --name ИМЯ_БАЗЫ --password ПАРОЛЬ_POSTGRESQL --apply
```

Первая команда только подсчитывает устаревшие записи: строки старого мониторинга `quiz_live` старше 24 часов без привязки к назначениям и просроченные сеансы администратора. Вторая удаляет их. Завершённые тесты, ответы и архивные результаты сохраняются. Просроченные сеансы администратора также удаляются автоматически во время работы.

## Сборка

```powershell
cd desktop
go test ./...
go build -trimpath -o OPP-test.exe .
```

Тест с PostgreSQL запускается при `OPP_TEST_POSTGRES=1`. GitHub Actions тестирует сервер с PostgreSQL, собирает EXE для Windows x64 и проверяет запуск командой из примера. После успешной сборки из `main` файл публикуется в релизе `site-latest`.
